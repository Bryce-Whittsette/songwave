# SongWave 0.5.10 — Clarity and accessibility

Public Preview · November 27, 2026 · build 20

Choose **SongWave → Check for Updates…** and approve the update. [Download for Mac](https://github.com/Bryce-Whittsette/songwave/releases/download/v0.5.10/SongWave-0.5.10-AppleSilicon.dmg).

## What changed

- **Clearer setup and recovery:** screen-reader headings, contextual Retry actions, and a native progress-indicator role for visual music activity. Automated checks now cover these views in CI.
- **Reduce Motion:** the beat pulse keeps a fixed size and brightness, with no animated interpolation. Level and recent-beat text remain available. Hidden views do no visual polling.
- **Both feels more separated:** detected percussion briefly comes forward while the vocal texture dips, then returns smoothly. A short complementary texture helps distinguish overlapping carriers without raising the output ceiling.
- **Accessibility purpose:** the README describes the goal of helping deaf and hard-of-hearing listeners connect with music through touch and visual rhythm, along with the listener validation still needed.

The native monochrome appearance, isolation model and separation algorithm are unchanged. Actual tactile clarity and comfort still need listener feedback. This preview remains unnotarized.

Both still uses one shared Light spectrum. Existing detected onsets duck the vocal bed with a 32 ms recovery constant. A 10 ms complementary carrier accent redistributes 22% of the percussion budget; its level is normalized within the prior mix's ceiling. No separation model, onset detector, extra audio lookahead or event is introduced. Regressions cover quiet attacks under a loud voice, colliding carriers, vocal recovery, output bounds and suppression/reset behavior.

The full audio/DSP, setup/recovery, privacy, signed-feed and mobile-core regression suite remains part of validation. The iPhone prototype is unchanged and has no public download.
