# SongWave 0.5.9 — First connection

Public Preview · November 27, 2026 · build 19

Choose **SongWave → Check for Updates…** and approve the update. [Download for Mac](https://github.com/Bryce-Whittsette/songwave/releases/download/v0.5.9/SongWave-0.5.9-AppleSilicon.dmg).

## What changed

- **First connection:** after new-user audio permission setup, watch music activity and choose a brief trackpad test. The test generates no speaker audio, runs only when clicked, and asks whether you felt it. You can enter recovery or continue without confirmation.
- **Listening help:** one connection view for trackpad availability, audio capture, selected app and pause reason, with relevant Retry and Settings actions. Copy diagnostics without song titles, recordings, personal paths or personal device names.
- **Clear visual feedback:** a monochrome beat indicator and music-level meter alongside the signal monitor, with text and accessibility labels. Reduce Motion removes pulse scaling.
- **Focused player:** listening state, Output, Feel and Intensity stay in front. **Other sources · link or file** groups optional sources; **Tools…** groups EQ, tuning, genre, keyboard lighting, patterns and Ultra.

Existing users are not forced through onboarding again. An unfinished new-user check can resume; continuing without confirmation dismisses it and leaves the tactile test unverified. Run it again from Listening help. First-time physical sensation and comfort still require listener feedback. The AI isolation engine and iPhone prototype are unchanged.

<summary>Developer notes</summary>

Setup preview uses unmuted capture with haptic output disabled at session creation. Only explicit Test trackpad schedules three 16 ms requests at level 0.35 across a sub-second sequence. Cancellation, shutdown and active calls block or stop the test. Missed timer windows are skipped; an incomplete sequence enters recovery. These bounds are software limits, not a manufacturer safety or comfort rating.

Rechecking restores the previous file/player, position and attached pattern; dismissing a check restores its selection without silently resuming. First-success state rejects stale test callbacks and requires explicit listener confirmation. Saved capture setup is separate from runtime verification. Recovery never bypasses call, speech or non-music video filtering. Diagnostics are constructed from numeric version/system data, validated hardware model and categorical states; raw error descriptions, track titles, filenames, bundle IDs and output-device names are not accepted by the formatter.

Visual beat peaks are retained across UI publication intervals so onsets between display updates are not lost. The indicator shares the visibility-aware visual subscriber and does not add audio lookahead or a background polling loop. Its level represents analyzed music activity, not actuator movement.

Validation includes pure state/privacy tests, hostile diagnostic strings, visual onset expiry/suppression, fake-hardware preview/test/cancellation/call checks, and existing audio/DSP/update regressions. Native UI checks do not substitute for physical confirmation, a VoiceOver user study or measured hearing-accessibility benefit. This preview remains unnotarized.
