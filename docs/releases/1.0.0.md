# SongWave 1.0 — Keep listening

November 27, 2026 · Mac build 24

**Already have SongWave?** Choose **SongWave → Check for Updates…**, then approve downloading and installing. New here? [Download for Mac](https://github.com/Bryce-Whittsette/songwave/releases/download/v1.0.0/SongWave-1.0.0-AppleSilicon.dmg), open the DMG and drag SongWave into Applications. Finish setup and play music normally. No song link required.

## What changed

- **Faster updates:** smaller signed downloads where possible, automatic checks about once an hour, and approval before installation. Automatic checks can be turned off.
- **Calmer visuals:** a fixed-size Beat mark fades gently, listening text stays steady between beats, and Ultra adds a glow. Reduce Motion keeps feedback still.
- **Clearer orientation:** setup explains listening, visual feedback, grouped tools and updates. Existing listeners get a short one-time guide with their preferences retained.
- **Listening continuity:** confirmed Spotify/Music playback survives brief Dictation metadata interruptions. Recognized calls still pause haptics.
- **Low bass and recovery:** stable low-bass cycles can contribute a soft tactile layer. Recovery preserves Haptics off and distinguishes playback errors from recording-access errors.

The isolation engine, listening modes and monochrome/native appearance are unchanged. SongWave explores music through touch and sight for deaf and hard-of-hearing listeners; accessibility benefit still needs listener validation.

**Compatibility:** Apple silicon, macOS 14.2+, Force Touch trackpad. Tested hardware remains an M4 MacBook Air. The app is ad hoc signed and **not notarized by Apple**; [installation help](../troubleshooting.md#macos-wont-open-the-app). The iPhone prototype is source-only, with no public download.

<summary>Developer notes and validation</summary>

Sparkle 2.10.1 creates v4 delta patches against up to three recent signed release archives. Release preparation verifies each base before extraction, reconstructs the target, compares file contents/permissions/symlinks, checks the app signature, signs each patch with the existing Keychain key, and verifies the resulting feed/assets. A full ZIP remains available. CI repeats feed/patch signature checks before advancing the monotonic public feed. Signing keys are never exported or placed in CI.

The scheduled check interval is 3,600 seconds. Automatic installation stays disabled. A real-framework policy test uses a disposable bundle and isolated defaults without starting a check; real patcher tests reject corrupt patches and mismatched bases. Feed tests cover malformed patch URLs, duplicate/invalid source builds, lengths and signatures. Release verification includes the actual signed patches, not only generated test fixtures.

The visual cue uses existing display publications rather than its own 30 Hz timeline. Its geometry and listening-state text stay stable; Reduce Motion disables interpolation and pulsing opacity. Native fixtures cover setup, upgrade orientation, labels, roles, grouping, visibility and haptics-off feedback without capture or motor activation.

Dictation routing excludes CoreSpeech from capture sources and briefly retains a previously confirmed player during activity/metadata gaps. Call suppression is unchanged. The bass envelope adds bounded causal period evidence to the existing low-pass signal, with no extra FFT, model or lookahead; the output cap remains unchanged. Synthetic bass tests span 25–80 Hz across five sample rates, quiet input, DC, voiced harmonics and silence. These tests do not establish song-level recall, physical latency or motor endurance. A brief isolated sub-bass hit may still be missed.

Recovery regressions cover haptics-off preservation after an unconfirmed setup check and generic playback errors that previously appeared as capture failures. Existing isolation/model files and listening-mode boundaries are retained. Apple Developer ID signing, notarization/stapling and broader hardware/listener testing remain unfinished.
