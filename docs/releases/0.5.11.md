# SongWave 0.5.11 — Connection and recovery

Public Preview · November 27, 2026 · build 21

Choose **SongWave → Check for Updates…** and approve the update. [Download for Mac](https://github.com/Bryce-Whittsette/songwave/releases/download/v0.5.11/SongWave-0.5.11-AppleSilicon.dmg).

## What changed

- **Recovery stays together:** Listening help starts at the first status. Trackpad, capture, app and listening retries stay in recovery during setup; choose Run setup check for another sensation test. Retrying the trackpad preserves any separate playback error.
- **Keep your place:** retrying a local file preserves its position and manual haptics-off choice. A live retry waiting for permission also preserves that choice. Local files do not request recording access.
- **Honest audio status:** setup distinguishes audio arriving now from audio detected earlier. Permission success and meter activity never count as a felt trackpad test.
- **No surprise restart:** a permission check finishing after you close the flow saves its result without reopening setup or starting playback.
- **Easier optional sources:** click anywhere on the Other sources label to show or hide links and files. Setup guidance now correctly describes Beat, Voice and Both in either output mode.

The main player retains its everyday listening controls, with optional links/files and advanced tools grouped separately. The isolation engine, haptic rendering and native monochrome direction are unchanged. This preview remains unnotarized.

<summary>Developer notes and validation</summary>

This audits roadmap items 2 and 3 already implemented in 0.5.9–0.5.10. The four recovery sections and privacy-safe formatter were present; this release fixes transitions and session context. Setup recovery retries use unmuted capture with haptic output disabled and do not schedule the explicit tap test. A support-operation generation invalidates deferred permission continuations after Stop, close or completion. Local-file health takes priority over unrelated recording-permission failures.

Real-controller regressions cover capture/app/listening retries, probe failure/recovery, explicit sensation state, current versus historical audio, local-file position/bypass, a live bypassed retry through permission recovery, and late permission completion after closing. Diagnostics tests inject private titles, artists, filenames, device names and raw error text into the real controller; only allowed categories and numeric system facts reach the report.

The native fixture now includes the production Console, without the production app's updater/menu lifecycle. Fake permission/audio/hardware edges keep tests non-actuating. Eight UI tests cover labels/roles/reading order, permission → explicit test → confirmation, in-place retries, compact-window scroll reset, grouped optional/advanced controls and reduced-motion states in light/dark. The ordinary regression suite, app build/signature verification and iPhone prototype compilation remain in CI.
