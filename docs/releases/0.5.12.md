# SongWave 0.5.12 — Visual listening

Public Preview · November 27, 2026 · build 22

Choose **SongWave → Check for Updates…** and approve the update. [Download for Mac](https://github.com/Bryce-Whittsette/songwave/releases/download/v0.5.12/SongWave-0.5.12-AppleSilicon.dmg).

## What changed

- **Clearer visual rhythm:** a larger monochrome Beat cue and explicit state text sit at the top of the main Signal Monitor, above the technical trace. Quiet reported events get a clear cue too.
- **Separate music level:** one labeled meter keeps percentage and dB readings, making level distinct from beat activity and manual Intensity.
- **Listen with haptics off:** visual feedback continues while listening, including when the Haptics switch is off. Silence and Stop clear the display.
- **Motion preferences:** Reduce Motion keeps pulse size and brightness fixed while retaining text and level feedback.

Visual feedback already existed in 0.5.11; this improves its clarity and placement rather than adding another display. Setup/recovery remain available. The native monochrome direction, isolation engine and haptic rendering are unchanged. This preview remains unnotarized.

<summary>Developer notes and validation</summary>

The main view uses a listening layout of the existing BeatLevelIndicator. Its two labeled groups replace duplicate level bars, retain the dB readout, and reserve a fixed pulse frame to avoid layout shifts. The new presentation sits above the spectrum trace, separate from Stop and Intensity. It consumes SignalDisplay's existing analyzed signal and visibility-aware schedule; there is no new capture stream, model, detector, lookahead, motor command or background polling loop. The simulation menu exists only in the disposable test fixture.

Presentation regressions cover bounded opacity/scale, nonfinite/extreme RMS, dB formatting, independent beat and level values, silence and Reduce Motion. Native coverage adds a main-listening scenario in light/dark and normal/reduced-motion states at a forced 810 × 640 content size. With haptics off, it requires one labeled passive progress role and a positive signal level, checks visibility and no overlap with Stop/Intensity, then verifies silence and Stop. Existing setup/recovery/accessibility, full audio/DSP/update regressions, app build/signature verification and iPhone prototype compilation remain in CI.

The cue reflects detected events from the current analyzed signal; focus, isolation and source restrictions remain relevant. Simulated tests and screenshots do not validate temporal legibility, hearing-accessibility benefit or physical synchronization. Listener feedback remains necessary. No mobile binary or signing/notarization workaround is introduced.
